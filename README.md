# Shoko Analytics

MVP локального Windows-приложения: ручной запуск, настройка источников, подготовка изменений, короткое подтверждение, обязательная резервная копия и проверка результата записи. Чёрный интерфейс соответствует согласованному макету v7.

## Запуск готовой сборки

Откройте `Shoko Analytics.lnk` в папке проекта или `Запустить.cmd`. Само приложение находится в `dist/ShokoAnalytics/ShokoAnalytics.exe`.

Сохраняйте всю папку `dist/ShokoAnalytics`: рядом с EXE находятся `app` с файлами программы и `runtime` с официальным Python 3.13.16 и библиотеками. Установка Python и Node пользователю готовой сборки не нужна. Нужен Windows 10/11 x64 с Microsoft Edge WebView2 Runtime и .NET Framework 4.8.

Готовая поставка больше не использует PyInstaller: небольшой EXE запускает отдельный Python с действительной подписью Python Software Foundation. Собственный EXE не подписан; подпись Python не выдаётся за подпись Shoko. [Устройство поставки и проверка Kaspersky](docs/WINDOWS_DISTRIBUTION.md).

По умолчанию рабочая папка — `%LOCALAPPDATA%/ShokoAnalytics`; она создаётся автоматически. При первой настройке можно выбрать другую. В ней находятся настройки, планы, исходные CSV, копии и журнал. Фоновый автозапуск не используется: локальный сервер доступен только на `127.0.0.1` во время работы окна и закрывается вместе с приложением.

## Первая настройка

1. Рабочая папка.
2. Приказ_цены_2026.xlsx и книга начислений за месяц отчётного дня; при переходе исторических дат в прошлый месяц — отдельная книга начислений за него. Выберите дату обработки. Для месячных файлов путь поддерживает `{year}`, `{yy}` и `{month}`, например `C:/data/{month}-{yy}/Начисление_{month}-{yy}.xlsx`.
3. Отдельная тестовая копия книги с листом «Предложение цен» и колонками A:C (класс, модель, год), либо копия Google-таблицы. Подтвердите разрешение записи в копию. Для Google нажмите «Войти через Google», войдите через браузер и выберите таблицу и папку копий в обычном Google Drive. OAuth-клиент приложения встроен в сборку. Включите Google Sheets API и Google Drive API. [Подробная инструкция подключения](docs/GOOGLE_SIGN_IN.md).
4. CSV из Гаража: выберите вручную скачанный файл. Подключение Telegram в 0.1.0 отсутствует. На любом шаге можно нажать «Сохранить и выйти», даже если заполнена только часть полей. Продолжить настройку можно через «Настройки → Повторить первичную настройку»; сохранённые поля остаются заполненными. После сохранения мастер сам при запуске не открывается. Недостающие данные и подключения блокируют обновление, а не сохранение настроек.

Настройки хранятся в одном `settings.local.json` в рабочей папке и изменяются через экран настроек. Резервные копии настроек не создаются; старые копии настроек скрыты из списка «Копии». При выборе другой рабочей папки в стандартном расположении остаётся только `workspace.location.json` с адресом папки, без дубликата настроек. Результат каждой проверки файла или подключения показывается непосредственно под её кнопкой.

Можно создать отдельную локальную копию существующего XLSX через «Создать копию из шаблона». Исходный шаблон остаётся неизменным. Реальные книги, CSV, ключи и готовые настройки не поставляются с программой.

Для Google авторизация защищена Windows DPAPI и хранится отдельно в sessions/google.vault; пароли и токены в настройки и журнал не попадают. Вход можно отменить, повторить или удалить. Смена аккаунта отменяет ранее подготовленное обновление.

## Ежедневная работа

Выберите дату и нажмите **«Обновление»**. В подменю отметьте галочками нужные операции: импорт CSV, обновление Гаража, акционных водителей H, состава/простоев P:AC или цен F/G. **«Выбрать всё»** отмечает все пункты; единственная кнопка **«Обновить»** готовит общий план только выбранных изменений. Источник CSV выбирается вручную в настройках; ссылка на Гараж не требуется.

После подготовки подтвердите дату и выбранные операции кнопкой **«Обновить»** в коротком окне. Таблицы «Было → станет» и просмотра всего результата больше нет. Приложение повторно проверяет источники и цель, создаёт копии, записывает точный подготовленный план и сверяет результат. До подтверждения целевые таблицы не меняются. Изменение файлов или цели после подготовки блокирует запись. Если изменений нет, приложение сообщает, что данные уже актуальны, без записи и создания копий.

Настройки разделены на вкладки Файлы, Google и Общие. Содержимое прокручивается внутри одного окна; сохранение доступно внизу. Во время проверки, подготовки и записи видны индикатор активности, текущий этап и время ожидания. На странице «Копии» показываются резервные копии Google Drive. История скрыта; технические события доступны в журнале разработчика. Google-копия открывается в браузере; локальную книгу можно скачать ZIP-архивом. Технический журнал — текстовое поле во вкладке «Разработчик», которая включается в настройках. Отменить можно подготовку; во время записи закрытие окна блокируется.

В новых **BF-копиях** светло-жёлтым выделяются прежние значения ячеек, которые обновление записало, очистило или пересчитало. Рабочие листы ради подсветки не перекрашиваются; нижележащие правила оформления BF сохраняются. Подсветка проверяется чтением после сверки значений.

## Границы MVP

В версии 0.1.0 Windows-приложение использует системное хранилище доверенных сертификатов для Google HTTPS. Ошибки сертификата, таймаута, соединения и авторизации различаются. «Проверить статус» читает только сведения о Google-таблице и наличие листа «Предложение цен»; полный снимок ячеек загружается при подготовке обновления.

Полный локальный цикл проверен на искусственных XLSX/CSV, отдельное Windows-окно — на этом ПК. На разрешённых Google-копиях проверены полная резервная копия, настоящая запись частями, расчёты, BF-копии и нулевые повторные планы. Последний прогон: 94 307 изменений в пяти частях, семь повторов без изменений, 332 автоматических теста (331 успешен, один системный пропуск Windows). Текущих комментариев в последней копии не было: перенос непустых обсуждений этим прогоном не подтверждён. Подробности — [журнал проверок](docs/QA.md). Автоматическое получение из Telegram и расписание отложены до второй версии. Боевые таблицы не использовались.

Действует согласованная цепочка **DOCX + три RTF**, вместе с импортом CSV и командой Гаража. Конфликтующие Google №2/№3 и старый объединённый Python-расчёт не запускаются. [Имена файлов, формулы и затрагиваемые листы](docs/DOCX_RTF_PARITY.md).

Перед записью в Google создаётся самостоятельная полная Google-таблица с текущими открытыми комментариями и ответами. Копия проверяется чтением: расположение, все листы, содержание комментариев и их ячейки. Закрытые обсуждения по согласованию не архивируются. Если копирование или сверка не удались, запись не начинается. Возможный таймаут создания не приводит к автоматическому повтору: неопределённая копия может остаться в папке Google Drive. Автоматическое восстановление, откат после сетевой ошибки и защита от одновременной правки Google другим пользователем не заявляются. После неподтверждённой сверки смотрите журнал разработчика и сохранённую копию.

Версия приложения — **0.1.0**. Её меняют только по явному запросу пользователя; исправления и повторные сборки номер не меняют.

## Разработка

Python 3.13, Node 24, React/Vite, pywebview/WebView2, компилятор C# из .NET Framework Windows. Запуск сборки из PowerShell:

```powershell
powershell -File tools/build.ps1 -Python python
```

Скрипт создаёт окружение, собирает UI, проверяет SHA256 и подписи официального Python, устанавливает закреплённые runtime-зависимости, собирает запускающий EXE и выполняет тесты на Python из готовой поставки. После smoke-проверки и сверки манифеста сборка заменяется, прежняя папка сохраняется в `build` для отката. Ярлык создаётся в папке проекта; `tools/create-shortcut.ps1 -Desktop` создаёт ярлык на рабочем столе. `tools/build-portable.ps1 -StageOnly` готовит проверяемый кандидат без замены установленного приложения. Старый `ShokoAnalytics.spec` оставлен только для сравнения прежней упаковки и в обычной сборке не используется.

Для сборки с настроенным входом через Google передайте `-OAuthClient "C:/private/oauth-desktop.json"` в `tools/build.ps1`. Конфигурация Desktop OAuth включается только в локальный дистрибутив; ключи, пользовательские токены и настройки не коммитятся. GitHub Actions собирает приложение без частной OAuth-конфигурации.

Для проверки интерфейса разработчиком:

```powershell
.venv/Scripts/python.exe main.py --browser --data-dir runtime/local-qa
```

Флаг `--browser` показывает локальный адрес в терминале. В этом режиме пути вводят вручную; системный выбор файла и открытие папки работают в Windows-окне. `--smoke` и `--ui-smoke` предназначены только для проверки сборки. GitHub Actions выполняет сборку и тесты на Windows, результат сохраняется артефактом.

Ключи, сессии, рабочие выгрузки и runtime никогда не коммитятся. Разработка ведётся в ветках и PR. [Проверки и сравнение дизайна](docs/QA.md).


В «Обновлении» две подвкладки: «Запуск» (дата, проверка статуса, обновление) и «Источники» (пути и отдельные проверки). Настройка путей выполняется в настройках. Перед записью кроме полной копии создаются BF-копии изменяемых существующих листов; имена и идентификаторы действующих листов сохраняются. BF и архивы располагаются рядом с оригинальными листами. Список BF-копий входит в подтверждаемый план. Старые BF-копии сохраняются, новые получают уникальные имена.

На странице разработчика доступны журнал, диагностика приложения, подробности новых ошибок Google, автономный тест на встроенных примерах и подсчёт занятого места. Встроенный тест не подключается к Google и работает с временными искусственными файлами.
