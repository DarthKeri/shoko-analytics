# Shoko Analytics

MVP локального Windows-приложения: ручной запуск, настройка источников, подготовка изменений, просмотр «Было → станет», обязательная резервная копия и подтверждённая запись. Чёрный интерфейс соответствует согласованному макету v7.

## Запуск готовой сборки

Откройте `Shoko Analytics.lnk` в папке проекта или `Запустить.cmd`. Само приложение находится в `dist/ShokoAnalytics/ShokoAnalytics.exe`.

Сохраняйте всю папку `dist/ShokoAnalytics`: рядом с EXE лежат необходимые библиотеки. Установка Python и Node пользователю готовой сборки не нужна. Нужен Windows 10/11 x64 с Microsoft Edge WebView2 Runtime.

По умолчанию рабочая папка — `%LOCALAPPDATA%/ShokoAnalytics`; она создаётся автоматически. При первой настройке можно выбрать другую. В ней находятся настройки, планы, исходные CSV, копии и журнал. Фоновый автозапуск не используется: локальный сервер доступен только на `127.0.0.1` во время работы окна и закрывается вместе с приложением.

## Первая настройка

1. Рабочая папка.
2. Книга средних цен/простоев и книга начислений. Выберите дату обработки. Для месячных файлов путь поддерживает `{year}`, `{yy}` и `{month}`, например `C:/data/{month}-{yy}/Начисление_{month}-{yy}.xlsx`.
3. Отдельная тестовая копия книги с листом «Предложение цен» и колонками A:C (класс, модель, год), либо копия Google-таблицы. Подтвердите разрешение записи в копию. Для Google нужен ключ **сервисного аккаунта**, включённые Google Sheets API и Google Drive API, доступ аккаунта к выбранной таблице и папка копий на общем диске компании (Shared drive). Ссылку на папку задайте в настройках Google и нажмите «Проверить папку копий». Обычная папка в «Моём диске» не подходит: у сервисного аккаунта нет собственного места для хранения. OAuth-ключ приложения другого типа не подходит.
4. CSV из стороннего бота: ручной выбор или подключение своего Telegram-аккаунта. На любом шаге можно нажать «Сохранить и выйти», даже если заполнена только часть полей. Продолжить настройку можно через «Настройки → Повторить первичную настройку»; сохранённые поля остаются заполненными. После сохранения мастер сам при запуске не открывается. Недостающие данные и подключения блокируют обновление, а не сохранение настроек.

Настройки хранятся в одном `settings.local.json` в рабочей папке и изменяются через экран настроек. Резервные копии настроек не создаются; старые копии настроек скрыты из списка «Копии». При выборе другой рабочей папки в стандартном расположении остаётся только `workspace.location.json` с адресом папки, без дубликата настроек. Результат каждой проверки файла или подключения показывается непосредственно под её кнопкой.

Можно создать отдельную локальную копию существующего XLSX через «Создать копию из шаблона». Исходный шаблон остаётся неизменным. Реальные книги, CSV, ключи и готовые настройки не поставляются с программой.

## Ежедневная работа

Вставьте ссылку на Гараж, выберите дату и нажмите **«Обновление»**. В ручном режиме подтвердите, что выбранный CSV относится к этой ссылке. В автоматическом режиме приложение отправляет ссылку боту от имени подключённого пользователя.

Проверьте сводку, таблицу изменений и при необходимости весь результат. **«Подтвердить и записать»** повторно проверяет источники и цель, создаёт копию, записывает показанный план и сверяет значения. До подтверждения целевые таблицы не меняются. Изменение файлов или цели после просмотра блокирует запись.

Настройки разделены на вкладки Excel, Google, Telegram и Приложение. Содержимое прокручивается внутри одного окна; сохранение доступно внизу. Во время проверки, подготовки и записи видны индикатор активности, текущий этап и время ожидания. «История» показывает результаты записи; «Копии» разделены на Google Drive, Excel и прежние снимки. Google-копия открывается в браузере; локальную книгу можно скачать ZIP-архивом. Технический журнал — текстовое поле во вкладке «Разработчик», которая включается в настройках. Отменить можно подготовку; во время записи закрытие окна блокируется.

## Границы MVP

В версии 0.2.0 Windows-приложение использует системное хранилище доверенных сертификатов для Google HTTPS. Ошибки сертификата, таймаута, соединения и авторизации различаются. «Проверить статус» читает только сведения о Google-таблице и наличие листа «Предложение цен»; полный снимок ячеек загружается при подготовке обновления.

Полный локальный цикл проверен на искусственных XLSX/CSV, отдельное Windows-окно — на этом ПК. Доступ к предоставленной тестовой Google-таблице проверен чтением в 0.1.2. Новое копирование в корпоративный Shared drive, перенос комментариев и настоящая запись требуют отдельной проверки после настройки папки. Telegram требует отдельной проверки с конкретным ботом. Боевые таблицы не использовались.

Автоматическое получение CSV требует ответа бота с привязкой к отправленному сообщению или ссылкой в подписи. Если бот отвечает по другой схеме, используйте ручной CSV до настройки его протокола. Проверка статуса не отправляет боту запрос выгрузки.

Применены правила **основного** legacy `update_google_sheets.py`; альтернативные RTF/TXT не смешиваются. Неизвестный скрипт внутри Google-таблицы, который далее использует «Выгрузка_Бот_Гараж», не воспроизводится. Нужен эталон заказчика для окончательной приёмки расчётов. [Точные правила и ограничения](docs/IMPLEMENTATION.md).

Перед записью в Google создаётся самостоятельная полная Google-таблица с текущими открытыми комментариями и ответами. Копия проверяется чтением: расположение, все листы, содержание комментариев и их ячейки. Закрытые обсуждения по согласованию не архивируются. Если копирование или сверка не удались, запись не начинается. Возможный таймаут создания не приводит к автоматическому повтору: неопределённая копия может остаться в папке Google Drive. Автоматическое восстановление, откат после сетевой ошибки и защита от одновременной правки Google другим пользователем не заявляются. После неподтверждённой сверки смотрите историю и сохранённую копию.

## Разработка

Python 3.12, Node 24, React/Vite, pywebview/WebView2. Запуск сборки из PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File tools/build.ps1 -Python python
```

Скрипт создаёт окружение, устанавливает зависимости, собирает UI, выполняет тесты, собирает EXE и создаёт ярлык в папке проекта. Параметр `tools/create-shortcut.ps1 -Desktop` создаёт ярлык на рабочем столе.

Для проверки интерфейса разработчиком:

```powershell
.venv/Scripts/python.exe main.py --browser --data-dir runtime/local-qa
```

Флаг `--browser` показывает локальный адрес в терминале. В этом режиме пути вводят вручную; системный выбор файла и открытие папки работают в Windows-окне. `--smoke` и `--ui-smoke` предназначены только для проверки сборки. GitHub Actions выполняет сборку и тесты на Windows, результат сохраняется артефактом.

Ключи, сессии, рабочие выгрузки и runtime никогда не коммитятся. Разработка ведётся в ветках и PR. [Проверки и сравнение дизайна](docs/QA.md).
