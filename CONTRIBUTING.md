# Разработка

1. Постановка задачи и критерии приёмки фиксируются в GitHub Issue.
2. Изменения выполняются в отдельной ветке: feature/<name>, fix/<name> или docs/<name>.
3. Перед pull request выполняются проверки, подходящие изменению. В описании указываются результат и ограничения проверки.
4. Изменения проходят review через pull request. main содержит согласованные изменения.
5. Не загружать credentials.json, токены, Telegram-сессии, реальные выгрузки, персональные данные или локальные настройки.
6. Тестировать на синтетических данных и явно разрешённых копиях таблиц. Боевые таблицы вне текущего объёма.
7. Изменение расчётов требует документированных соответствий источников, столбцов и ожидаемого результата.

Технологический стек, автоматические проверки и механизм защиты main будут определены отдельно. Наличие этого файла не означает, что защита ветки уже включена.
