# Вход Google одной кнопкой

В установленной настроенной сборке пользователь открывает Настройки → Google, выбирает «Мой Google-аккаунт» и нажимает «Войти через Google». Аккаунт и доступ выбираются в системном браузере Google; пароль приложение не получает. Отдельный OAuth JSON пользователю выбирать не нужно. Ссылка на таблицу и папка копий по-прежнему задаются в настройках.

## Подготовка сборки разработчиком

Для приложения один раз регистрируется OAuth-клиент Google типа Desktop app. В проекте нужны Google Sheets API и Google Drive API; аудитория/доступные пользователи настраиваются в Google Cloud. Наличие кнопки не отменяет политики организации или список OAuth Test users.

При сборке передайте путь к скачанной конфигурации Desktop app: `./tools/build.ps1 -OAuthClient <путь-к-Desktop-JSON>` или `./tools/build-portable.ps1 -StageOnly -OAuthClient <путь-к-Desktop-JSON>`. Низкоуровневый сборщик принимает `assemble --oauth-client <путь>`.

Сборщик валидирует тип Desktop и адреса Google и помещает в app/assets/oauth-desktop.json только client_id, client_secret, auth_uri, token_uri. Пользовательские токены, ключи сервисного аккаунта и исходный JSON целиком не копируются. Desktop-приложения являются публичными OAuth-клиентами и не могут хранить client_secret как серверный секрет; защита входа остаётся на PKCE, проверке state и loopback. См. [официальную схему Google](https://developers.google.com/identity/protocols/oauth2/native-app). Никаких паролей или токенов в сборку/Git не передавайте.

Конфигурацию реального проекта не коммитим; oauth-desktop.json игнорируется Git. CI без этого параметра делает универсальную сборку: для входа нужно выбрать собственный Desktop JSON в «Дополнительных настройках Google». Для распространения внутри компании создавайте сборку с её OAuth-клиентом.

## Сохранение и смена подключения

Refresh/access tokens хранятся отдельно от установки, в sessions/google.vault рабочей папки, под DPAPI пользователя Windows. Если встроенный клиент совпадает с прежним, сохранённый вход остаётся действующим после удаления внешнего пути из настроек. Сам исходный JSON не удаляется. Изменение OAuth-клиента требует повторного входа. Собственный OAuth-клиент в дополнительных настройках имеет приоритет над встроенным. Выход из аккаунта удаляет локальную сессию; параметры самого приложения остаются в сборке.

Предпросмотр, явное подтверждение, проверенная полная резервная копия и сверка после записи обязательны независимо от способа входа. Версия остаётся 0.1.0.
