# Вход Google одной кнопкой

Пользователь открывает Настройки → Google и нажимает «Войти через Google». Аккаунт и доступ выбираются в системном браузере Google; пароль приложение не получает. В интерфейсе нет полей OAuth/credentials.json, выбора сервисного аккаунта и ручного выбора способа подключения. После входа появляются выбор целевой таблицы, папки резервных копий и проверки доступа.

## Подготовка сборки разработчиком

Для приложения один раз регистрируется OAuth-клиент Google типа Desktop app. В проекте нужны Google Sheets API и Google Drive API; аудитория/доступные пользователи настраиваются в Google Cloud. Наличие кнопки не отменяет политики организации или список OAuth Test users.

При сборке передайте путь к скачанной конфигурации Desktop app: `./tools/build.ps1 -OAuthClient <путь-к-Desktop-JSON>` или `./tools/build-portable.ps1 -StageOnly -OAuthClient <путь-к-Desktop-JSON>`. Низкоуровневый сборщик принимает `assemble --oauth-client <путь>`.

Сборщик валидирует тип Desktop и адреса Google и помещает в app/assets/oauth-desktop.json только client_id, client_secret, auth_uri, token_uri. Пользовательские токены, ключи сервисного аккаунта и исходный JSON целиком не копируются. Desktop-приложения являются публичными OAuth-клиентами и не могут хранить client_secret как серверный секрет; защита входа остаётся на PKCE, проверке state и loopback. См. [официальную схему Google](https://developers.google.com/identity/protocols/oauth2/native-app). Никаких паролей или токенов в сборку/Git не передавайте.

Конфигурацию реального проекта не коммитим; oauth-desktop.json игнорируется Git. Для работающего входа сборка должна содержать встроенный OAuth-клиент. Если его нет, приложение предлагает установить настроенную сборку; ручного выбора JSON в интерфейсе больше нет. CI без частной конфигурации по-прежнему пригоден для автоматических тестов. В установленную локальную сборку 0.1.0 включён проверенный встроенный клиент.

## Сохранение и смена подключения

Refresh/access tokens хранятся отдельно от установки, в sessions/google.vault рабочей папки, под DPAPI пользователя Windows. Если встроенный клиент совпадает с прежним, сохранённый вход остаётся действующим. Кнопка входа использует встроенный клиент и очищает устаревшие пути к внешнему OAuth JSON и ключу сервисного аккаунта в настройках; сами внешние файлы не удаляются. Изменение OAuth-клиента требует повторного входа. Выход из аккаунта удаляет локальную сессию; параметры самого приложения остаются в сборке.

Предпросмотр, явное подтверждение, проверенная полная резервная копия и сверка после записи обязательны независимо от способа входа. Версия остаётся 0.1.0.

## Проверка упрощённого интерфейса

На Python итоговой поставки выполнено 235 тестов: 234 прошли, один пропущен из-за ограничения Windows на символические ссылки. В отдельном профиле проверены отсутствие полей ключей до/после входа, выбор таблицы и папки, сохранение настроек и переход с прежней локальной цели/сервисного режима на встроенный Google-вход. При таком переходе старый локальный путь не принимается за ID Google-таблицы, разрешение записи требуется задать для новой цели. В UI-проверке вход и списки Google имитировались, внешние HTTP-запросы были запрещены; реальный пользовательский аккаунт не подключался и не сбрасывался. EXE/WebView2 запустились на отдельном тестовом профиле; прежний запускающий EXE сохранён.
