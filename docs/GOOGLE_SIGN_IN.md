# Вход через свой Google-аккаунт — Shoko Analytics 0.1.0

> Архив первоначального способа подключения. Поля файлов и выбор способа входа удалены из текущего интерфейса. Актуальные шаги: **Настройки → Google → Войти через Google**, затем выбрать таблицу и папку копий. Пользовательский OAuth-файл и credentials.json не нужны. Подготовка встроенного клиента разработчиком описана в [GOOGLE_LOGIN.md](GOOGLE_LOGIN.md).

Этот способ нужен для создания резервных копий в обычной папке «Моего диска». В приложении выбирается **Мой Google-аккаунт**, а вход и согласие на доступ проходят на сайте Google в обычном браузере. Пароль Google в Shoko Analytics не вводится.

## Один раз подготовить OAuth-файл

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и выберите тот же проект, где включали Google Sheets API. Можно использовать существующий проект приложения.
2. В **APIs & Services → Library** проверьте, что включены **Google Sheets API** и **Google Drive API**.
3. Перейдите в **Google Auth Platform → Branding**. Если платформа ещё не настроена, нажмите Get started. Задайте название Shoko Analytics, почту поддержки и контактную почту разработчика.
4. В **Audience** для обычного Google-аккаунта выберите **External**. В режиме **Testing** добавьте свой Google-адрес в **Test users**. Для Workspace-входа можно выбрать Internal, если этот вариант доступен в проекте и пользователи принадлежат организации.
5. В **Data Access → Add or remove scopes** разрешите `https://www.googleapis.com/auth/spreadsheets` и `https://www.googleapis.com/auth/drive`. Drive требуется для полной копии существующей таблицы и работы с папкой, указанными ссылками. Это широкое разрешение Drive; ограничение записи приложения по подтверждённой тестовой таблице сохраняется.
6. В **Clients → Create client** выберите тип **Desktop app / Приложение для компьютера**. Название — Shoko Analytics. Нажмите Create и скачайте JSON. Адрес перенаправления вручную задавать не требуется: приложение использует локальный адрес 127.0.0.1 на свободном порту.
7. Сохраните файл в постоянной папке. Его стандартное имя начинается с `client_secret_`; при желании переименуйте в `google_oauth_client.json`.

Это отдельный файл OAuth-клиента. Прежний `credentials.json` с типом `service_account` для входа пользователя не подходит. Не отправляйте OAuth-файл и файл сессии в GitHub или переписку.

Официальные шаги: [создание Desktop app](https://developers.google.com/workspace/guides/create-credentials#desktop-app), [вход для установленных приложений](https://developers.google.com/identity/protocols/oauth2/native-app).

## Подключить приложение

1. Откройте **Настройки → Google**. Если требуется, выберите расположение таблицы Google Sheets.
2. В разделе **Вход в Google** выберите **Мой Google-аккаунт**.
3. В поле **OAuth-файл приложения** нажмите Выбрать и укажите скачанный JSON. Кнопка **Проверить OAuth-файл** проверяет его формат без открытия браузера.
4. Нажмите **Войти через Google**. Приложение сначала сохранит настройки, затем откроет браузер.
5. Выберите аккаунт, у которого есть доступ к тестовой таблице и папке копий. Разрешите запрошенные Drive и Google Sheets. Вход и согласие завершаете вы сами; приложение ждёт до трёх минут. Его можно отменить кнопкой **Отменить вход**.
6. Вернитесь в приложение. В блоке входа появится адрес подключённого аккаунта. Это подтверждает сохранённый вход; доступ к конкретным файлам проверяется отдельно.
7. Укажите ссылку на тестовую Google-таблицу, подтвердите разрешение записи в копию. В поле **Папка для резервных копий** вставьте ссылку на обычную папку в вашем Google Drive.
8. Нажмите **Проверить целевую таблицу** и **Проверить папку копий**, затем Сохранить настройки. На главном экране можно готовить обновление. Запись по-прежнему происходит только после просмотра и подтверждения, а перед ней создаётся и проверяется Google-копия.

При входе своим аккаунтом отдельно открывать доступ сервисному аккаунту не требуется. Достаточно прав вашего Google-пользователя на выбранные файлы и папку. Реальная возможность создания копии также зависит от квоты хранилища и ограничений Google.

## Повторные запуски и отключение

Авторизация хранится в `sessions/google.vault` рабочей папки и защищена Windows DPAPI. Настройки остаются в одном `settings.local.json`; токены в него, в журнал и в резервные копии не попадают. При необходимости приложение автоматически обновляет токен и сохраняет его в том же зашифрованном файле. Перенос vault другому пользователю Windows не переносит доступ.

**Войти в другой аккаунт** заменяет сохранённый вход только после успешной авторизации. **Выйти из аккаунта** удаляет локальный вход; глобальный доступ OAuth-приложения можно отдельно отозвать в [подключениях Google-аккаунта](https://myaccount.google.com/connections). Смена аккаунта или выход отменяют старый предпросмотр — обновление нужно подготовить заново.

У External-приложения со статусом **Testing** Google выдаёт для этих разрешений refresh token на **7 дней**. Затем потребуется повторный вход. Для постоянной эксплуатации настройте подходящий режим публикации; Google может потребовать проверку OAuth-приложения или разрешение администратора организации. [Правило срока действия Google](https://developers.google.com/identity/protocols/oauth2/#expiration).

## Если вход не проходит

- **Выбран ключ сервисного аккаунта**: скачан прежний credentials.json. Создайте именно OAuth client ID типа Desktop app.
- **access_denied / приложение недоступно пользователю**: проверьте Test users и выбранный Google-адрес; в Workspace также ограничения администратора.
- **redirect_uri_mismatch / invalid_client**: проверьте тип Desktop app и скачайте его JSON заново. Web application для этого сценария не подходит.
- **Время входа истекло**: нажмите Войти через Google ещё раз; ответ предыдущей попытки не используется.
- **Авторизация истекла / invalid_grant**: войдите заново; проверьте режим Testing и время Windows.
- **SERVICE_DISABLED**: включите Drive API и Sheets API именно в проекте OAuth-клиента.
- **Нет прав на таблицу или папку**: подключённый Google-пользователь должен иметь необходимые права. Копирование не выдаёт дополнительные разрешения.
- **storageQuotaExceeded**: проверьте свободное место в Google Drive и выбранный способ входа. Приложение не пропускает запись без успешной резервной копии.

Проверка статуса и сам вход не изменяют Google-таблицу и не создают резервную копию. Реальное копирование начинается после подтверждения подготовленного обновления.
