# Проверка MVP — 13.10.2026

## Подтверждено локально

- Python 3.12: **33 теста прошли** (`python -m unittest discover -s tests -v`). Все рабочие книги/CSV в тестах искусственные; файлы исходного архива не менялись.
- Vite: production-сборка прошла; frontend встроен в Windows-дистрибутив.
- PyInstaller: собран `dist/ShokoAnalytics/ShokoAnalytics.exe` с библиотеками.
- Готовый EXE с `--smoke`: exit 0, backend и встроенные файлы UI загрузились.
- Готовый EXE с `--ui-smoke`: WebView2 открыл отдельное окно; DOM содержит название Shoko Analytics и заголовок «Настройка приложения», окно завершило проверку и закрылось. Это проверка загрузки настоящего окна, не ручная проверка всех системных диалогов.
- Созданы ярлыки в папке проекта и на рабочем столе.
- В Browser/IAB через реальный локальный backend пройден мастер: выбор путей, дата, разрешённая копия, CSV, завершение с проверками.
- Через UI пройден цикл **54 изменения → просмотр → подтверждение → резервная копия → запись → сверка**. Проверена история, открытие копии и скачивание ZIP. Исходное состояние книги сохранено полностью.
- Проверены индивидуальная/общая проверки, назад/вперёд с сохранением полей, включение/скрытие разработчика и текстовое поле реальных логов.
- Дополнительно прочитаны настоящие архивные книги за май: 373 строки простоев и 1975 строк начислений. После исправления заголовков и регистра моделей выполнен офлайн-расчёт для 315 сопоставленных строк шаблона в памяти, без предупреждений; ни цель, ни Google не использовались, исходные SHA-256 остались прежними. Это проверка совместимости источников, а не сверка с эталоном заказчика.
- В актуальном интерфейсе проверены рабочая сводка с датами, сохранение разрешения тестовой копии и его отзыв; в консоли IAB ошибок нет.

## Что покрывают тесты

Правильные F/G/H и исторические показатели; перенос месячного хвоста; сохранение текстовых заголовков и нормализация регистра/пробелов известных моделей; сохранение нетронутых формул и оформления; отсутствие записи до подтверждения; полный файл резервной копии; single-use плана; изменение источника/цели после просмотра; повреждение плана; отказ копирования; сбой сверки с сохранением копии; потерянный файл; ошибочное число; Excel-формула без кэша; неподтверждённый CSV; запрет боевого ID и совпадения с источником; отзыв разрешения; проверка без записи; неверный CSV/неизвестная модель; локальная блокировка двух экземпляров; защита HTTP token/Origin; запрет GET-записи; один Google batchUpdate с текстовыми значениями; Telegram без отправки в проверке статуса, привязка CSV к запросу, отказ от чужого/неверного файла, DPAPI roundtrip.

DPAPI проверяется в отдельном процессе полного жизненного цикла приложения, включая проверку Telegram после шифрования/расшифровки. На этой Windows-среде повторная загрузка Win32-модуля при пересоздании тестовых потоков давала аварийное завершение; изоляция интеграционного теста устраняет влияние на unit-тесты. Приложение использует один Telegram-поток на рабочую папку. Проверка реальной авторизации остаётся отдельной приёмкой.

## Сравнение с согласованным дизайном v7

Эталон: `shoko-dark-v7.html`, отрендеренный локально через IAB. Эталон и актуальный экран просмотрены через `view_image` в одном проходе. Скриншоты: [эталон](qa/accepted-v7.jpg), [реализация](qa/mvp-update-final.jpg), [план без изменений](qa/mvp-preview-final.jpg).

| Проверено | Эталон / реализация | Решение |
|---|---|---|
| Фон и контраст | Чёрный основной фон `#0d0d0d`, тёмный sidebar, белые подписи | Сохранено, цвет проверен computed CSS |
| Шрифты | Segoe UI, заголовок 30px, вкладки 16px | Совпадают по computed CSS |
| Подвкладки | Запуск / Источники, половина ширины каждая, общая рамка и тёмный активный фон | Равные ширины подтверждены DOM; подчёркивания отсутствуют |
| Стрелки | В рабочей области над заголовком | Настоящая история переходов; иконки Lucide вместо неподключённых standalone-маркеров эталона |
| Ошибки | Ниже рабочей сводки, рамка и светлая левая граница | Сохранено; реальный текст вместо симуляции |

Проверены CSS viewport **1180×850**, минимальная ширина Windows-окна **860×650** и дополнительная адаптивность **390×844**: горизонтального переполнения документа нет. IAB сохраняет JPEG и может масштабировать/обрезать доступную область контейнера; размеры DOM проверялись отдельно. Screenshot QA не выдаётся за ручной native UI QA.

Проверка текстов первого экрана: «Обновление данных», «Запуск», «Источники», «Ссылка на Гараж», «Дата обработки», «Рабочая сводка», «Ошибки», «Проверить статус», «Обновление» сохранены. Удалённые пользователем блоки готовности, тестовые подписи возле запуска и подчёркивания не возвращались. Отличаются только значения файлов/даты/статусов и фактический режим получения CSV. Мастер, пустые состояния и страница предпросмотра содержат необходимые рабочие сообщения вместо симуляции.

Исправленные при QA расхождения: сохранение даты календаря, сброс несохранённой формы при polling, переход к записи при блокированной навигации, сохранённый признак разрешённой копии, слишком длинный предпросмотр. Полный результат получил заголовки A/B/C и горизонтальную прокрутку без переноса по одной букве. Длинная таблица теперь прокручивается внутри страницы, с доступной кнопкой подтверждения. Согласованный дизайн перенесён и проверен по перечисленным пунктам; пиксельное тождество встроенной карточке не заявляется.

## Не проверено / ограничения

**Настоящие Google Sheets и Telegram-бот не подключались.** Google write проверен на моделируемом API-запросе, Telegram — на искусственных ответах и настоящем DPAPI. Нужны ключи, тестовый ID, Telegram-вход и диалог конкретного бота. Самостоятельный эталон бизнес-расчётов заказчика пока отсутствует.

Не выполнены ручные тесты Windows file picker и закрытия окна посреди настоящего сетевого запроса, Google timeout/восстановления и одновременного чужого редактирования. Автоматический откат/восстановление не реализован. Excel не пересчитывает формулы в Python: сохранённые исходные кэши нужны для расчётов, оставшиеся формулы пересчитаются в Excel/Google; их будущие вычисленные значения не предсказываются.

GitHub Actions добавлен для повторяемой сборки. Его облачный результат следует проверять отдельно от описанных локальных проверок.
