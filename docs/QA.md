## Вход пользователя Google — версия сохранена 0.1.0

- Добавлены OAuth Desktop app и внешний браузер с PKCE S256, случайным портом 127.0.0.1, проверками Host/path/state. Авторизация не выполняется во встроенном WebView. Ожидание до 180 секунд, отмена из интерфейса и при закрытии приложения.
- Refresh token защищён Windows DPAPI в sessions/google.vault; сохраняется при обновлении токена в тот же файл. Токены/код/client secret не входят в public_state, settings.local.json и журнал. Выход удаляет локальную сессию, смена аккаунта/клиента отменяет прежний план; identity проверяется и перед записью. Сервисный аккаунт остаётся отдельным способом входа; обычная папка Google Drive не блокируется по типу диска.
- 83 автоматических теста: реальный PKCE официальной библиотеки; локальный callback (чужой Host/state, повторные параметры, неверный путь); удачный OAuth, отказ, неполные разрешения, таймаут, отмена, защищённое хранение и восстановление сессии, refresh, подмена OAuth-клиента и аккаунта, выход, отказ записи по старому плану. DPAPI отдельно проверен в настоящем Windows-процессе. Ошибки квоты, API, scopes и прав больше не сводятся к единому сообщению 403.
- В браузере проверены экран Google, отмена ожидания, удачный вход вымышленного demo@example.test и выход. В этой проверке не открывались настоящие OAuth-страницы и не создавались облачные файлы. Прокрутка и доступность сохранения проверены при 1120×720, 860×560 и 390×844, ошибок в консоли нет.
- Финальные EXE и WebView2 прошли --smoke и --ui-smoke в отдельных пустых папках. Проверен номер 0.1.0 в Python, frontend и выводе сборки; ZIP ShokoAnalytics-0.1.0-Windows.zip и ярлыки обновлены. OAuth-зависимость включена в сборку, ключей/настроек/vault в дистрибутиве нет.
- Требует приёмки пользователем: создать свой OAuth Desktop app, подтвердить вход/разрешения в Google, проверить доступ к выбранной папке/таблице и создание настоящей копии после подтверждения плана. Собственные Google-файлы и настройки пользователя в разработческих тестах не изменялись, Telegram не подключался. Подробные шаги — docs/GOOGLE_SIGN_IN.md. Google может требовать повторный вход через 7 дней для External/Testing; это ограничение OAuth-проекта, а не локального хранилища.

## Google HTTPS и проверка статуса — 0.1.2

- **49 автоматических тестов**: дополнительно проверены системное доверие Windows с обязательной проверкой сертификата/имени узла, различение TLS/таймаута/соединения/авторизации, исключение секретов из сообщений и получение только метаданных при проверке статуса Google.
- Реальная причина прежнего сообщения «нет соединения или таймаут» — `SSLCertVerificationError: self-signed certificate in certificate chain`. Через системное хранилище сертификатов Windows чтение метаданных предоставленной тестовой копии вернуло HTTP 200. Исправление использует truststore 0.10.5 на старте Windows-приложения; проверка подлинности HTTPS включена.
- В собранном EXE до финального облегчения статуса прошли проверки предоставленных Excel, ручного CSV и доступа к Google-копии. CSV содержит 21 строку данных. Запущенная подготовка отменена по просьбе пользователя о самостоятельном тестировании; запись в Google не запускалась. В Git не включаются ключ, идентификатор пользовательской копии, реальные данные, планы или локальные настройки.
- Финальная проверка статуса Google использует только метаданные таблицы и наличие листа «Предложение цен». Содержание ячеек и снимок для резервного копирования по-прежнему читаются при подготовке/подтверждении; это может занимать больше времени, чем проверка доступа.
- Финальное тестирование на пользовательских данных выполняет пользователь. Проверка настоящей записи в Google и Telegram остаётся отдельной приёмкой.

## Что покрывают тесты

Правильные F/G/H и исторические показатели; перенос месячного хвоста; сохранение текстовых заголовков и нормализация регистра/пробелов известных моделей; сохранение нетронутых формул и оформления; отсутствие записи до подтверждения; полный файл резервной копии; single-use плана; изменение источника/цели после просмотра; повреждение плана; отказ копирования; сбой сверки с сохранением копии; потерянный файл; ошибочное число; Excel-формула без кэша; неподтверждённый CSV; запрет боевого ID и совпадения с источником; отзыв разрешения; проверка без записи; неверный CSV/неизвестная модель; локальная блокировка двух экземпляров; защита HTTP token/Origin; запрет GET-записи; один Google batchUpdate с текстовыми значениями; Telegram без отправки в проверке статуса, привязка CSV к запросу, отказ от чужого/неверного файла, DPAPI roundtrip.

DPAPI проверяется в отдельном процессе полного жизненного цикла приложения, включая проверку Telegram после шифрования/расшифровки. На этой Windows-среде повторная загрузка Win32-модуля при пересоздании тестовых потоков давала аварийное завершение; изоляция интеграционного теста устраняет влияние на unit-тесты. Приложение использует один Telegram-поток на рабочую папку. Проверка реальной авторизации остаётся отдельной приёмкой.

## Не проверено / ограничения

**Настоящие Google Sheets и Telegram-бот не подключались.** Google write проверен на моделируемом API-запросе, Telegram — на искусственных ответах и настоящем DPAPI. Нужны ключи, тестовый ID, Telegram-вход и диалог конкретного бота. Самостоятельный эталон бизнес-расчётов заказчика пока отсутствует.

Не выполнены ручные тесты Windows file picker и закрытия окна посреди настоящего сетевого запроса, Google timeout/восстановления и одновременного чужого редактирования. Автоматический откат/восстановление не реализован. Excel не пересчитывает формулы в Python: сохранённые исходные кэши нужны для расчётов, оставшиеся формулы пересчитаются в Excel/Google; их будущие вычисленные значения не предсказываются.

GitHub Actions добавлен для повторяемой сборки. Его облачный результат следует проверять отдельно от описанных локальных проверок.
